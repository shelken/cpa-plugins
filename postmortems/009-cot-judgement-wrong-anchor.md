# 拿复述型提示词判思考输出

**日期**: 2026-09-14
**影响**: 思维链判据间歇判红，误判为插件缺陷；排查期间还因整文件回滚摧毁未提交改动
**发现人**: shelken（「你他妈为什么一直失败」「问这种脑瘫问题测试思考」「还在胡说八道」）

## 问题

`verify-chat.go` 对 `qwenworkcn/pro` 运行时断时续报 `思维链输出 FAIL 流式增量里没有 reasoning_content`，同一份代码同一凭据时而 16 项全绿时而挂 1 项。

## 现象

同一提示词「只回复两个字:收到」连打 6 次，reasoning 字符数按 effort 档分布：

```text
low     44 / 0 / 53 / 0 / 0 / 0      空 4/6
medium  0 / 0 / 0 / 147 / 0 / 50     空 4/6
high    237 / 15 / 0 / 59 / 51 / 0   空 2/6
max     260 / 397 / 473 / 368 / 359 / 261   空 0/6
```

参考实现（`pi-qwenwork-provider`，协议蓝本）同账号同提示词打同一上游 8 次，5 次为空；插件链路 8 次空 3 次。

## 根因

- **错误假设 1**：上游对任何提示词都输出思考，判据挂在哪一轮都一样。实际约束是上游按请求决定是否输出思考，概率由 effort 档与问题难度共同决定；复述型提示词（复述暗号、只回两个字）在低档实测空 4/6。判据挂在复述轮等于在测上游的采样。
- **错误假设 2**：把「提示词琐碎」当成唯一原因。那时还没测 effort 这个混淆变量，结论下早了。
- **错误假设 3**：`git checkout scripts/verify-chat.go` 只是回滚一处改动。实际约束是整文件 checkout 会连带摧毁该文件其他未提交改动（此处的 `-token-file` 支持），必须是范围化回滚。
- **缺失检查点**：清单查找用硬编码 `workbuddy/` 前缀剥离模型 id，换成 `qwenworkcn/pro` 后清单整个查不到，思考深度段被跳过，`思维链输出` 判据根本没执行，却仍打印「16 项通过」，制造了通过的假象。判据被跳过这件事没有进失败计数。

## 修复

- 思考判据改挂「推演型提示词 + 该模型最高档」，那里上游必出思考（3 轮实测 1072～1782 字）。
- `checkCoT` 增加契约分支：上游自述 `usage.reasoning_tokens > 0` 而流里无思考帧即 FAIL，专抓插件丢帧，这类回归与上游采样无关。
- 清单查找改为剥掉最后一个 `/` 之前的部分，不写死插件前缀。
- 恢复被整文件 checkout 摧毁的 `-token-file` 支持。
- 插件 `executor.go` 的 effort 缺省值改读清单 `defaultReasoningEffort`，与 workbuddy 对齐（原为硬编码 `high`）。
- 验证：`verify-chat.go` 连跑 3 轮，每轮 `16 项通过, 0 项警告, 0 项失败`，`思维链输出` 与 `思考深度传递` 均实际执行。

## 预防

- 判据只挂在该行为确定发生的场景上；先量测行为在候选场景下的发生频率，再决定挂载点，禁止「反正都会发生」。
- 判据被跳过必须计入失败或至少计入警告，不能只打印一行提示就继续报全绿。
- 判据必须落在可重复执行的脚本里。只写在文档手工步骤中的判据，会因为密钥、凭据、多轮消息任一环断裂而静默不执行，验收格空着也无人察觉（工具调用一格即此）。
- 判定某个变量是原因前，先把同类变量枚举并逐个量测；一次只测一个变量，跑完再下结论。
- 回滚单个改动用范围化手段（按行还原、按 hunk 还原），禁止对含未提交改动的文件整文件 `git checkout`。
- 共享工具里出现某个具体插件的硬编码标识（前缀、id）就是缺陷信号，改为参数化或通用剥离。
