# 声明与实现脱节：手写契约表与未实现的参数

**日期**: 2026-09-13
**影响**: 一次字段修正指令里 8 条有 5 条是假阳性；两次审计因为参数未生效而审计了错误的会话，得出「聊天接口 0 样本」的错误结论
**发现人**: 主代理（复核阶段自查）

## 问题

`pi-codebuddy-provider/scripts/audit-traffic-diff.ts` 里有两处声明没有对应的执行点。

用法注释声明了 `--session`、`--latest`、`--json` 三个参数，但 `main()` 从不解析参数，永远取最新一次会话。`TARGET_INTERFACES` 是手写的「插件应发送什么字段」的表，与 Go 实现和真实抓包都脱节：表里留着桌面端根本不发的 `tool_choice` 与 `x-session-id`，又漏了客户端实发的 `x-domain`、`x-agent-purpose`、`x-product`。

后果是审计报告把表的缺陷当成了代码的缺陷。我据此给实现子代理下过「必须补 8 个头部」的指令，其中 5 个其实早已发送。

## 现象

无论是否传 `--session`，审计都只分析最新会话：

```text
$ bun run scripts/audit-traffic-diff.ts --session WorkBuddy_20260913_171327.json
[最新抓包] 文件: WorkBuddy_20260913_174259.json      # 参数被忽略
```

聊天接口的样本在另一份会话里，于是报告显示 0 样本，我据此判断「聊天接口没抓到」。

## 根因

错误假设：工具文档里写了的参数就是实现了的；那张手写表就是实现的现状。

实际约束：声明（注释、表）与实现之间没有任何一致性检查点。表在一处手工维护，代码在另一处维护，漂移是必然的。未实现的参数也没有调用点或测试能揭穿。

## 修复

- 实现 `--session`（文件名片段必须唯一命中，否则列出候选并以退出码 1 结束），删除从未实现的 `--json` 声明。
- 把表按插件实际发送的集合重写，并在注释里写明：表必须与 Go 实现同步演进，`Missing` 才是必须处理项，`Extraneous` 只是信息项。
- 下指令前先用实现侧的集合与抓包重算差集，不直接采信工具报告。

## 预防

- 新增任何声明时同时给出执行点或测试，做不到就删掉声明；工具改动后逐个参数在真实场景跑一遍，参数生效与否必须有可观察的输出差异。
- 用工具输出驱动修改前，先确认该输出依赖的输入（表、配置、会话）是最新的，并用第二个独立手段复算关键结论。
- 手写契约表要么由实现生成，要么在改动实现的同一次提交里更新。
