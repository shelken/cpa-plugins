# verify-chat 按带前缀模型 id 查清单 miss

**日期**: 2026-09-14
**影响**: workbuddy 0.1.4 生产验收时思考深度检查被静默跳过，降级为 13 项通过且缺关键一项
**发现人**: 逐行读 verify-chat 输出，发现「[思考深度] 跳过: 清单未声明该模型的档位」

## 问题

模型 id 前缀化后，宿主 `/v1/models` 返回 `workbuddy/hy3`，verify-chat.go 用这个完整 id 去 `static-config.json` 查模型档位，清单里存的是裸 id `hy3`，查不到。脚本没有报错，只是打印一行「跳过」继续跑完，最后给出「13 项通过 0 失败」的绿结论。照单全收绿灯的话，档位传递这一核心验收项实际没验。

## 现象

```bash
go run scripts/verify-chat.go -base http://192.168.69.60:8317 -model workbuddy/hy3
#   静态清单里没有该模型, 能力判据将退化为默认假设
# [思考深度] 跳过: 清单未声明该模型的档位
# 结论: 13 项通过, 0 项警告, 0 项失败
```

## 根因

实际约束：id 前缀化是注册层概念，静态清单保持裸 id（上游协议保真）。缺失检查点：改模型 id 形态时，没有排查「按 id 反查清单」的所有读方；verify-chat 的降级路径（查不到就跳过）吞掉了本应暴露的 miss，输出仍显绿。

## 修复

查清单前剥前缀，请求仍用完整 id：

```go
if strings.EqualFold(doc.Models[i].ID, strings.TrimPrefix(*model, "workbuddy/")) {
```

修后思考深度对比正常执行并 PASS（low 推理 2146 字 < high 7331 字）。

## 预防

- 改任何对外 id 的形态时，grep 全仓该 id 的消费点（含按 id 反查配置/清单的脚本），逐个确认前缀处理，verify-chat.go 的清单查找就是这次漏掉的一处
- 读验收脚本输出时把「跳过」「退化」「默认假设」当作红灯处理，绿结论必须逐项核对没有静默降级
