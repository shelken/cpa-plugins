# 身份档与登录档分离，默认全部走桌面端

桌面端实测本身就是多身份混用（对话、鉴权、额度、配置各用不同身份），独立 codebuddy CLI 则是另一套身份与另一套登录路径，因此不能把客户端身份与登录方式绑成一个开关。身份档决定请求头怎么写，登录档决定凭据怎么拿，两者正交，默认都取 `desktop`。配置由宿主通过 `plugin.register` 下发，切换后重启宿主生效，覆盖范围只有对话与鉴权两条链路，其余接口维持桌面端分层不变。

## Status

accepted

## Considered Options

- 单一开关同时决定身份与登录：配置面最小，但无法回答「只想换登录方式」这类需求。
- 全接口各备两套身份：静态清单体积翻倍，而实测差异只出现在对话与鉴权。
- 登录档默认留在 CLI：CLI 路径生产验证更久，但会让默认行为与默认身份来自两套基准。

## Consequences

- 静态清单需为对话与鉴权各存两套头部模板。桌面端登录用 `platform=workbuddy`，CLI 用 `platform=cli`。
- 凭据文件保留桌面端返回的全部字段，含 `sessionState`、`scope`、`domain`，裁剪后无法恢复。
- 桌面端登录实测样本仅一次（`revest-app/output/WorkBuddy_20260913_174259.json`），CLI 登录作为兜底档保留。
- 身份档与登录档允许不同源，这种组合在任何单一官方客户端上都不存在，属刻意选择。
- 私有仓方案撤回。插件源码直接进 `cpa-plugins` 公开仓，只有抓包与审计工具留在 `pi-codebuddy-provider`，不进插件仓。
- 本 ADR 修订 ADR-0003 的「唯一基准」表述为「默认基准」
